# lexicon-atelier · 术语工坊

> 从行业报告、研究材料中提炼专业术语，生成结构化术语词条，并排成术语词典式的公众号文章。

## 问题

行业报告和研究材料里，专业术语密度很高。这带来两个麻烦：

**对读者**：读到不认识的词，要么硬读过去，要么翻到文末的术语表——翻过去就回不来了。传统做法只有两个选择，都不好：

- 术语表统一放文末 → 读者要来回跳转，阅读节奏断掉
- 把解释直接塞进正文 → 一段话被注解切碎，正文变得臃肿

**对作者**：整理术语这件事本身就很费时间。要从几万字的报告里把术语捞出来、判断哪些值得解释、给每条写定义、还要保证全文编号一致——手工做一遍，半天没了，而且很容易漏、很容易前后编号对不上。

## 方案

把这两件事合成一条流程，拆成三层产出物：

| 产出物 | 解决什么 |
|---|---|
| **术语词典**（JSON + Markdown） | 结构化资产，可检索、可复用、可给同事，也是后续更新的唯一数据源 |
| **术语词典式文章**（HTML 片段） | 术语解释出现在它第一次出现的地方，左右两栏——左边读正文，右边看解释，零跳转 |
| **配图**（封面 + 方图） | 与文章同色系的矢量配图，直接用作公众号封面 |

核心机制是**术语锚点**：给每个术语登记它在正文里可能出现的说法（别名），系统据此定位"第一次出现"，把术语卡片挂到那一段旁边。装不下的术语自动续排到段后，两列并排。

术语编号在词典、正文标记、右侧术语栏、文末附录四处严格一致——这是自动校验的，不一致会直接报错。

## 示例输入输出

完整示例见 [`examples/`](examples/) 目录，全部使用合成数据。

本 demo 完整产出 **16 条**术语（A1–E3，四组）；完整项目通常 30–45 条。

**想直接看成品**：下载仓库到本地，用浏览器打开 [`examples/demo/preview.html`](examples/demo/preview.html)——那是**实际跑出来的**完整文章，右上角有「复制到公众号」按钮，点一下就能粘进公众号编辑器。

> 为什么不能直接从 GitHub 上复制？因为能粘进公众号的是**浏览器渲染后的富文本**，不是文件本身。`.html` 在 GitHub 上只能看到源码，直接从文本编辑器复制粘贴过去会变成一堆标签。这个"最后一公里"的处理方式见 [`examples/demo/README.md`](examples/demo/README.md)。

下面是从 `input.md` 到产出的节选：

**输入**（[`examples/input.md`](examples/input.md) 节选）——一份抗体偶联药物（ADC）产业速览：

> 业内评估一条 ADC 管线，绕不开三个指标：**药物抗体比（DAR）**——平均每个抗体上挂了多少个毒素分子。太低打不死细胞，太高则抗体容易聚集、清除加快……**旁观者效应**：毒素从靶细胞渗出、杀死邻近抗原阴性细胞的现象。对异质性强的实体瘤是优势，但对正常组织则意味着**脱靶毒性**。

**输出**（[`examples/output.md`](examples/output.md) 节选）：

| 编号 | 中文名 | 英文名 | 分类 | 一句话定义 |
|---|---|---|---|---|
| A4 | 药物抗体比 | Drug-to-Antibody Ratio, DAR | 技术 | 平均每个抗体分子上偶联的毒素数量，是决定疗效与耐受性的核心工艺参数 |
| A5 | 旁观者效应 | Bystander Effect | 技术 | 毒素从靶细胞渗出、杀伤邻近抗原阴性细胞的现象 |
| C1 | 突破性疗法认定 | Breakthrough Therapy Designation | 监管 | 早期临床显示显著优势即可申请的加速通道，换取与审评机构更密集的沟通 |
| E1 | 许可输出 | License-out | 产业 | 把早期管线授权给大型药企，换取首付款、里程碑付款与销售分成的变现方式 |

以及一份 10 节的成稿文章结构，术语以两栏形式嵌在正文里。

## 使用方式

1. 把 `SKILL.md` 放进你的 Claude Code 技能目录（通常是 `~/.claude/skills/lexicon-atelier/`）
2. 把你的报告原文（Markdown / 纯文本）放到工作目录
3. 对 Claude 描述任务，例如：

```
用 lexicon-atelier 处理 report.md，整理成术语词典 + 公众号文章。
文章标题「抗体偶联药物：靶向与毒素之间的工程学」，
作者署名 lainie-w。
```

4. 依次得到：术语词典 JSON/MD、公众号 HTML、带复制按钮的预览页、配套配图

如果你的环境里装了 `gzh-design` 排版技能，本技能会复用它来保证输出符合公众号平台规范；没有装也能用，但产出的 HTML 需要自己过一遍平台校验。

## 架构与依赖

本 skill 采用分层架构：

- **术语层（本 skill 核心贡献，完全自研）**
  - 术语提炼与分组
  - 术语词典结构化（JSON / Markdown）
  - 术语锚点定位（按别名优先级匹配首次出现）
  - 两栏投放逻辑（正文左栏 + 术语卡片右栏）
  - 编号一致性校验

- **适配层（本 skill 自研，薄）**
  - 把术语卡片数据翻译成排版引擎能接受的输入格式
  - 位于 `scripts/render_adapter.py`
  - 只做数据格式转换，不生成 HTML、不做样式

- **排版层（复用开源 skill）**
  - HTML 排版、公众号合规校验、复制到公众号的交互
  - 由社区开源的 gzh-design skill 完成

本 skill 在执行前会主动检查 gzh-design 是否安装，未安装时会询问用户，不会静默降级。

为什么要这样分：核心贡献自己写，非核心的排版复用成熟工具，
中间用适配层隔开——将来想换排版引擎，只需替换适配层，不动核心。

## 效果或价值

**术语层（本 skill 核心贡献）：**
- 从 1 万字报告中提炼 30–50 条术语，编号全文一致
- 术语解释出现在它第一次出现的段落旁，读者零跳转
- 词典 JSON 可直接复用给下一篇文章

**交付层（依赖 gzh-design）：**
- 排版后的 HTML 可直接粘贴进公众号
- `examples/demo/preview.html` 展示的是这一层的效果

> ⚠️ preview.html 的 HTML 排版由 gzh-design 生成，不是本 skill 的产出。

## 限制

诚实说明这个技能做不到什么：

- **术语解释依赖原文**。技能不会替原文补它没说的机制。原文没展开的地方，词条里就写"原文未展开"——不臆造。
- **别名需要人工判断**。术语在正文里第一次出现时用的说法（比如只用缩写、或换个措辞），系统猜不准，需要你确认。写偏了会导致术语卡片挂错段落。这是整个流程里最容易出错、也最需要经验的一步。
- **中文分栏高度是估算的**。浏览器无法在生成时真实测量文字高度，只能按字符宽度估算行数来做左右配平。极端情况下（大量英文、超长数字）两侧可能略有高低差，需要肉眼过一遍。
- **表格列数多时要转成卡片**。超过 4 列的表格挤不进正文栏宽，需要改成卡片式呈现——这一步目前是半自动的，脚本里备了几种卡片样式可以套。
- **不负责事实核查**。技能保证"数字、产品名、编号不被改动"，但不保证原文本身正确。原文有错，产出也会有错。
- **配图是几何抽象的**，适合数据/行业类内容；人物、场景类配图不在范围内。
