# lexicon-atelier · 术语工坊

## 目标

把一篇长文（行业报告、深度研究、白皮书）处理成三层产出物，且**术语编号在全文严格一致**：

1. **术语词典**：结构化词条（JSON + Markdown），每条含编号、中英文名、分类、一句话定义、三段详解、别名、原文出处
2. **术语词典式文章**：术语解释出现在它第一次出现的段落旁边，左右两栏；装不下的续排到段后
3. **配图**：与文章同色系的封面图与方图

## 适用场景

**用**：用户给出一篇含大量专业术语的长文，希望读者不必跳转到文末查词。

**不用**：
- 纯排版任务（那是排版技能的职责）
- 纯写作任务（本技能不创造内容，只重组与解释原文）
- 术语极少的文章（少于 15 个候选词，两栏版式反而割裂正文）

## 架构说明

本 skill 分三层：
1. 术语层（本 skill 核心）：术语提炼、词典结构化、锚点定位、编号校验
2. 适配层（本 skill）：把术语卡片翻译成排版引擎输入
3. 排版层（依赖）：调用 gzh-design 完成 HTML 排版与合规校验

如果环境中没有 gzh-design，本 skill 仍可产出术语词典 JSON/Markdown
和结构化的文章骨架，但 HTML 排版需要用户自行处理。执行前会先与你确认
（见「依赖检查」），不会静默降级。

## 依赖检查（执行前必做）

开始处理前，请先检查当前环境是否安装了 gzh-design skill：

1. 检查 ~/.codex/skills/ 和 ~/.claude/skills/ 下有没有 gzh-design
2. 如果有 → 正常走完整流程
3. 如果没有 → 询问用户：

   需要我帮你先安装 gzh-design 吗？还是只产出术语词典和文章骨架？"

不要静默降级，必须让用户明确知道当前处于哪种模式。

## 步骤

### 步骤 0 · 通读并判定两件事

**① 原文有没有现成的术语表？**
- **有**（如"第 01 章 术语速查表 A1–G7"）→ 抽取模式：术语清单、编号、定义直接取用，**不要自创编号**
- **没有** → 提炼模式：从全文提炼，按 A–G 分组自编号

**② 文章主体结构是什么？** 记下章节清单——目录、附录、参考文献都要与它对齐。

### 步骤 1 · 提炼术语

**核心判据：一个受过良好教育的非本行业读者，读到这个词会不会卡一下？**

会卡 → 收。不会卡 → 不收。词典的价值来自"解释的稀缺性"，混进常识条目会稀释它。

**该收**：行业专有缩写 / 监管类别与路径 / 具体技术路线 / 具体菌株分子靶点类专名 / 关键临床或业务终点概念 / 关键产品与企业 / **作者自创的分析框架** / **易被误读的数字口径**

> 最后两类最容易漏。作者自创的概念（如"双轨分化""0→1 兑现窗口"）往往不觉得自己"专业"，但它们是理解文章主线的钥匙。

**不该收**：学科基础名词 / 通用商业金融概念 / 日常生活概念（产品包装上就有的）/ 常识性分析工具 / 与已有条目重复的近义词

**按七组归类**（组名可随体裁改写，但编号首字母保持 A–G）：

| 组 | 覆盖 |
|---|---|
| A | 基础概念 |
| B | 产品与形态 |
| C | 监管与政策 |
| D | 技术与证据 |
| E | 产业与市场 |
| F | 企业与关键资产 |
| G | 判断与信号 |

**数量参考**：1 万字长文 → 35–50 条。少于 30 条多半漏了作者自创概念；多于 60 条多半混进了常识。

### 步骤 2 · 逐条写词条

每条九个字段。其中两个必须想清楚：

**一句话定义**（20–60 字）——会显示在正文右侧术语栏，必须一眼看懂，不绕。

**别名**——正文里定位"首次出现"的说法，**按优先级排列，先匹配到的生效**。这是全文最容易出错的一项：

```python
别名=['细菌性阴道病', 'BV']    # 正文首次出现写的是"细菌性阴道病BV"，两个都登记
别名=['复发']                  # 全称太长，正文只写简称，就用简称
别名=['Pre-NDA']               # 正文只会写缩写
```

- 写太泛（"复发""指南""口径"）→ 很早的段落就命中，术语卡片挂到无关段落旁
- 写太偏（照抄长括号说明）→ 正文根本匹配不到，术语进了词典却从不出现
- **不要写另一个术语别名的子串**。例：术语甲别名"抗体偶联药物"已经占用了那段文字，术语乙再用"偶联"就会定位到同一个位置，两个标记互相覆盖，后者投放不出徽标。改成语义独立的短语（如"偶联工艺"）即可。生成后跑徽标落位自检会把这个报出来。
- **不要选会跨越 Markdown 标记边界的短语**。原文写作 `**偶联**环节` 时，"偶联环节"在源码里被 `**` 隔开，匹配不到；要选"偶联过程"这类同一纯文本段内连续出现的说法。
- **实操**：先用主干词，再回原文搜一遍它第一次出现时用的到底是什么说法，把那个说法放到列表首位

**三段详解**（是什么 / 有什么作用 / 机制原理）供附录用。**必须从原文提炼，不引入原文没有的事实**。原文没展开的地方就写"原文未展开"，不要替它补。

### 步骤 3 · 编译词典

数据与逻辑分离：术语数据写在一个独立的数据文件里，编译脚本只负责校验与输出。校验必须通过：编号唯一、每组从 1 连续、三段详解齐备、别名非空——任一不满足直接报错退出。

### 步骤 4 · 装配文章

按以下骨架装配。**在术语第一次出现的段落处切两栏**：

```
头图卡（系列标识 + 日期 + 主标题·强调词 + 副标题 + 深色摘要条）
目录卡（章节索引）
00 核心观点
01–05 正文章节      ← 段落 / 表格 / 列表；术语首现处切两栏
06 风险提示
07 结语
08 附录：术语详解    ← 与 01 编号一一对应的完整词条
09 参考文献
署名段 + 结尾互动区
```

**两栏版式规格**：

- 左栏 `width:62%`、`box-sizing:border-box`、`padding-right:10px`、`min-width:0`
- 右栏 `width:38%`，内为浅底卡片
- 左栏正文字号 13px / 行高 1.85；右栏术语名 11px、英文名 9px、定义 10px
- 术语在正文里：橙色下划线 + 一枚橙色编号徽标，徽标数字 = 该术语在**本段**中的序号
- 右栏每条：编号徽标 + 中文名 + 「附录 X」标签 + 英文名 + 分类标签 + 一句话定义 + `是什么 / 有什么作用 / 如何工作 → 见附录 X`
- **编号按术语在左栏正文中出现的先后排**（不是按词典编号），保证正文里 ①②③ 的顺序与右栏从上到下一致

**配平规则**（浏览器无法真实测量文字高度，按字符视觉宽度估算行数）：

| 情况 | 处理 |
|---|---|
| 右栏明显更长（超过左栏高度 1.15 倍） | 留装得下的前 k 条在右栏，其余移到段后「本段术语（续）」，两列平分 |
| 左栏更长 | 把左栏正文按高度切成 1–3 行，术语均分到各行，每行各配一段术语栏 |
| 某行只有正文或只有术语 | 并入上一行，避免出现悬空栏 |

### 步骤 5 · 校验（强制，不许跳）

生成后必须跑平台合规校验，要求 **0 ERROR 且 0 WARNING**：

- 禁用 `<style>` / `<script>` / `<div>` / `class` / `id` / `float` / `display:grid` / `@media` / CSS 变量
- **所有文字节点必须被 `<span leaf="">` 包裹**——否则粘贴到公众号后样式整片丢失
- 半角标点与直引号必须全角化（`"` → `“ ”`，`'` → `’`），这是粘贴后最容易露馅的地方

### 步骤 6 · 三项自检

1. **徽标落位**：右栏每条术语都必须能在左栏正文里找到对应编号徽标，缺一个就报错
2. **编号一致**：正文徽标数 == 右栏术语条数
3. **标签配平**：`<section>` 开闭数必须相等

### 步骤 7 · 配图

生成与文章同色系的配图：主视觉应当是**文章核心判断的几何抽象**（而不是通用装饰）。手绘 SVG 后栅格化为 PNG——比 AI 生图更可控，色值能与排版精确对齐。

**图片不进 HTML**：公众号只认自己上传的图片，本地路径粘贴过去必然是裂图。配图单独交付 PNG，由用户在编辑器里手动上传。

### 步骤 8 · 交付

告知用户：产物路径、校验结论、以及"打开预览页 → 点复制按钮 → 编辑器粘贴"的操作路径。

## 输出格式

```
输出目录/
├── {STEM}_术语词典.json / .md        # 结构化词典
├── dist/{STEM}_排版_{主题名}.html     # 干净正文片段（纯 <section>），校验对象
├── preview_{名称}.html               # 带复制按钮的预览页
└── 配图/封面首图_900x383.png
    配图/配图_方形_500x500.png
```

**词典 JSON 结构**：

```json
{
  "标题": "…… · 术语词典",
  "术语总数": 16,
  "编号范围": "A1–E3",
  "收词原则": "只收需要解释的专业条目；常识性概念不列入。",
  "分组": { "A": "A 组 · 技术基础（A1–A6）" },
  "术语": [
    {
      "编号": "A1",
      "中文名": "抗体偶联药物",
      "英文名": "Antibody-Drug Conjugate, ADC",
      "分类": "技术",
      "组": "A 组 · 技术基础（A1–A6）",
      "别名": ["抗体偶联药物", "ADC"],
      "一句话定义": "用连接子把单克隆抗体与细胞毒小分子拼在一起、靠抗体导向在肿瘤局部释放毒素的药物形态。",
      "原文出现位置": "导言",
      "详细解释": {
        "是什么（定义）": "……",
        "用途（有什么作用）": "……",
        "机制原理（如何工作）": "……"
      },
      "附录锚点": "附录 A1"
    }
  ]
}
```

**文章 HTML**：纯 `<section>` 正文片段，**不要** `<!DOCTYPE>` / `<html>` / `<head>` / `<body>`——公众号编辑器只接受正文片段。

## 质量要求

1. **术语编号全文唯一且一致**：词典、正文徽标、右侧术语栏、附录，四处同一套编号。改编号时四处一起改，改完重跑自检。
2. **不篡改原文事实**：数字、产品名、公司名、审批编号、引用编号一个字都不能改。原文没说的不补，原文标"未查到公开证据"就保留这个说法。
3. **每个正文段落标 1–3 处橙色关键词**：即使原文没有任何加粗，也要主动标记。这是这套排版出现频率最高的视觉标记。

## 常见错误

| 症状 | 原因 | 处理 |
|---|---|---|
| 粘贴到平台后样式整片丢失 | 文字节点没被 `<span leaf="">` 包裹 | 跑校验脚本，它按 ERROR 报出未包裹片段 |
| 同一术语在一段里出现两个编号徽标 | 别名同时出现在加粗小标题和正文里，两处都投放了 | 整段共用一个"待投放"列表，投放后即移除 |
| 某个术语右栏有条目、正文里没徽标，且它的别名是另一个术语别名的子串 | 标记实现是"边替换边搜索"：先投放的那个把文本换成了占位符，后者再也找不到自己的文本 | ① 实现上改为"先在原文定位全部标记、重叠则跳过、最后统一拼接"；② 数据上把泛性别名换成语义独立的短语 |
| 右栏有条目、正文里没有徽标 | 别名带 Markdown 反斜杠转义（`Pre\-NDA`），定位时在转义文本里搜、渲染时在未转义文本里找 | 统一口径：去掉 Markdown 转义后再定位 |
| 编号列表全部从 01 开始 | 条目之间有空行，被解析成多个单元素列表 | 列表解析要允许条目间空行 |
| 附录组区间与条数对不上 | 增删术语后忘了同步硬编码的区间 | 组区间从数据算出来，不要硬编码 |
| 章节增删后编号跳号 | 目录、章节大编号、附录引言分散在多处 | 改成配置驱动；改完全文搜一遍旧编号 |
| 手机宽度截图看起来内容被裁切 | 桌面版 Chrome 有最小窗口宽度（约 500px），窄窗截图会被裁 | 这不是 bug。测手机版用 520px 宽截图 |
